# 0.2.1: Fix the blank NIKKE login CAPTCHA window

[简体中文](UPDATE-2026-09-26.zh-CN.md) · [README](../README.en.md)

## Symptom and cause

The official launcher opens, but its account verification window titled **LEVEL INFINITE CAPTCHA NEW** is white and never displays the slider.

In the tested setup, the launcher page uses `tbs_browser.exe`, while verification uses a separate `intl_service.exe` host with `INTLWebViewHelper.exe` children. The earlier launcher's rendering options did not reach this host. Adding the following options to the correct host made the slider visible; the user then completed verification manually:

```text
--disable-gpu --disable-gpu-compositing --in-process-gpu
```

This rendering workaround was verified in this configuration; other blank windows may have different causes. Network/page warnings alone did not establish a missing dependency. No WebView2 installation or certificate-check changes were needed for this repair.

## Verification scope

- Apple M4 Max, macOS 27.0, CrossOver 26.1.
- The slider appeared, the user completed it manually, and the official launcher displayed its signed-in home page.
- After updating to **NIKKE PC Global 152.8.13** and upgrading the old saved entry to the existing 0.2.0 runtime build, resource downloads completed and the lobby opened. The user confirmed responsive page navigation.
- No new long-session or combat test was performed in this round. Earlier combat reports used 152.8.11. Existing background-component limitations remain in [Validation](VALIDATION.md).

The wrapper forwards the launcher's arguments verbatim, inherits handles and returns the original service's exit status. It does not print arguments that could contain login information. The backup preserves the official service's bytes; WebView helper executables and DLLs remain unchanged. Only rendering options are added; verification is neither automated nor replaced.

## Install only the CAPTCHA fix

Requires Python 3 and MinGW-w64. Run from this repository's root; rebuilding the Wine kernel is unnecessary:

```sh
make webview
```

Alternatively, compile directly:

```sh
mkdir -p build
x86_64-w64-mingw32-gcc -O2 -s -Wall -Wextra -Werror -municode -mwindows \
    src/intl_service_wrapper.c -o build/intl_service.wrapper.exe
```

**Exit the game and launcher, then stop all programs in the target bottle through CrossOver.** Replace `YOUR_NIKKE_BOTTLE` with the bottle you actually use, for example `NIKKE-Compatibility`:

```sh
python3 scripts/install_webview_fix.py install \
    --prefix "$HOME/Library/Application Support/CrossOver/Bottles/YOUR_NIKKE_BOTTLE"
```

The default service directory inside the bottle is `drive_c/NIKKE/Launcher/intl_service`. For a different install location, use `--service-dir` with a bottle-relative directory. Do not select the whole Launcher directory or a symlink outside the bottle.

The installer saves `intl_service.original.exe` and a hash-only `.nikke-webview-fix.json`, then installs the compiled wrapper as `intl_service.exe`. Reinstalling the same build preserves the backup. Running related processes, unknown backups and updater-changed files cause it to stop without overwriting those files.

Keep using **your existing NIKKE compatibility entry in CrossOver**. Complete the slider yourself when it appears.

Read-only status check:

```sh
python3 scripts/install_webview_fix.py check \
    --prefix "$HOME/Library/Application Support/CrossOver/Bottles/YOUR_NIKKE_BOTTLE"
```

## Restore and future updates

Close the programs and stop the bottle first:

```sh
python3 scripts/install_webview_fix.py restore \
    --prefix "$HOME/Library/Application Support/CrossOver/Bottles/YOUR_NIKKE_BOTTLE"
```

After checking both file hashes, this restores the original service, retaining the backup and manifest for recovery or reinstallation. It only undoes the WebView fix; the Wine runtime, game resources and launcher entry are unchanged.

A launcher update may replace the wrapper. **Never copy an old backup over an updated service.** If the status check reports a changed service, preserve the files and use the official repair process to restore the current service first. Once you have confirmed it is the current official file, move the old `intl_service.original.exe` and `.nikke-webview-fix.json` to a separate local backup directory, then reinstall this fix. If you cannot establish file provenance, report the issue with sanitized details before proceeding.

If you manually installed an earlier fix and have an `.original.exe` without a manifest, **leave it alone if verification already works**. The installer refuses to guess the provenance of old backups. To migrate, preserve the old files and obtain the current original service through the official repair process above.

## Saved entry still using an older runtime?

This investigation also found a saved compatibility entry still using an early runtime. Updating the game or downloading GitHub source does not update that runtime, so fixing verification can expose a separate startup problem. This tool only changes browser startup. Follow the README's [runtime upgrade instructions](../README.en.md#updating-an-existing-installation) when needed. Version 0.2.1 adds no new ACE kernel fixes.
