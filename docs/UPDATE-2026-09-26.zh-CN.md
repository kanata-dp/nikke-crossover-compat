# 0.2.1：NIKKE 登录验证码白屏修复

[English](UPDATE-2026-09-26.en.md) · [返回首页](../README.md)

## 现象与原因

官方启动器可以打开，但账号安全验证弹出的 **LEVEL INFINITE CAPTCHA NEW** 窗口只有白色背景，无法看到滑块。

本次实测中，启动器页面使用 `tbs_browser.exe`，而验证码由独立的 `intl_service.exe` 启动 `INTLWebViewHelper.exe`。之前给启动器添加的渲染参数没有传到验证码宿主，因此启动器能正常显示，验证页面仍然白屏。给正确的宿主添加以下参数后，用户确认滑块出现并手动完成登录：

```text
--disable-gpu --disable-gpu-compositing --in-process-gpu
```

这是本次配置下验证有效的渲染兼容处理，不代表所有验证码白屏都由相同原因造成。网络或页面加载报错本身不能证明缺少组件；本次没有额外安装 WebView2，也没有关闭证书检查。

## 已验证到哪一步？

- Apple M4 Max、macOS 27.0、CrossOver 26.1。
- 验证码显示正常；用户手动验证后，官方启动器显示已登录。
- 游戏更新到 NIKKE PC 国际服 **152.8.13**；将本机旧固定入口的运行时升级为已有 0.2.0 构建后，资源下载完成并进入大厅，用户确认页面切换正常。
- 本轮没有新增长时间或战斗验证；此前的战斗记录属于 152.8.11。既有后台组件限制见 [验证记录](VALIDATION.md)。

此包装程序完整转发启动器传入的参数、继承句柄，并返回原服务的退出状态；不输出可能含登录信息的参数。原服务备份保持原字节，WebView helper 和 DLL 保持原样。它只添加渲染选项，不自动完成验证码，也不替换验证结果。

## 单独安装验证码修复

需要 Python 3 和 MinGW-w64。以下命令在仓库根目录执行；只构建这个小程序，无需重编兼容内核。

```sh
make webview
```

也可直接构建：

```sh
mkdir -p build
x86_64-w64-mingw32-gcc -O2 -s -Wall -Wextra -Werror -municode -mwindows \
    src/intl_service_wrapper.c -o build/intl_service.wrapper.exe
```

**先退出游戏和官方启动器，再在 CrossOver 中结束目标容器的所有程序。** 把下方 `YOUR_NIKKE_BOTTLE` 换成实际使用的容器名称，例如 `NIKKE-Compatibility`：

```sh
python3 scripts/install_webview_fix.py install \
    --prefix "$HOME/Library/Application Support/CrossOver/Bottles/YOUR_NIKKE_BOTTLE"
```

默认服务目录为容器中的 `drive_c/NIKKE/Launcher/intl_service`。若游戏安装在其他位置，用 `--service-dir` 指定容器内的相对目录；不要指向整个 Launcher 目录或容器外的链接目录。

安装器保存 `intl_service.original.exe` 和只含校验值的 `.nikke-webview-fix.json`，然后将编译的包装程序放到 `intl_service.exe`。再次安装同一构建不会反复覆盖备份。检测到正在运行的相关进程、未知旧备份或文件被更新时会停止，保留现有文件。

安装后继续从 **CrossOver 中原来的 NIKKE 兼容入口**启动。验证码出现后由你手动拖动滑块。

只读检查：

```sh
python3 scripts/install_webview_fix.py check \
    --prefix "$HOME/Library/Application Support/CrossOver/Bottles/YOUR_NIKKE_BOTTLE"
```

## 还原与后续更新

退出相关程序、结束容器进程后执行：

```sh
python3 scripts/install_webview_fix.py restore \
    --prefix "$HOME/Library/Application Support/CrossOver/Bottles/YOUR_NIKKE_BOTTLE"
```

它校验备份和当前文件后，恢复原服务，保留备份及清单用于恢复或再次安装。只撤销验证码修复，不改 Wine 运行时、游戏资源或启动入口。

官方启动器更新可能覆盖包装程序。**不要把旧备份直接复制到新版服务上。** 如果检查提示服务已变更，保留文件；先通过官方修复恢复当前版本服务。确认该文件确实为当前官方服务后，把旧 `intl_service.original.exe` 和 `.nikke-webview-fix.json` 移到另一个本地备份目录，再重新安装本修复。无法确认文件来源时请先提交已脱敏的问题说明。

曾手动安装早期修复、已有 `.original.exe` 但没有清单的用户：**如果验证码已正常，就保持现状**。新安装器会拒绝猜测旧备份的来源。需要迁移时，先保留旧文件，再按上述官方修复流程取得当前原文件。

## 固定入口仍指向旧运行时？

这次本机还发现旧“NIKKE 兼容版”入口仍使用早期运行时。升级游戏或下载 GitHub 源码不会自动更新它，所以修复验证码后仍可能遇到另一个启动错误。验证码工具只处理浏览器；需要升级兼容运行时的用户请遵循首页的 [旧版升级说明](../README.md#已安装旧版如何升级)。0.2.1 没有增加新的 ACE 内核修复。
